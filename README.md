# FL-AUP: Federated Learning with Adaptive Update Perturbation for Diabetes Prediction

Source code and experiment results for the paper **"Federated learning with adaptive update perturbation for diabetes prediction under non-IID data"**.

The project simulates two hospital clients (RS_01 and RS_02) with label-skewed (non-IID) data that train a Multi-Layer Perceptron collaboratively through **FedAvg**. Client updates are clipped and perturbed with Gaussian noise before aggregation, and three scenarios are compared over 50 communication rounds and five random seeds.

## Scenario names (code vs. paper)

| Code key | Paper name | Description |
|---|---|---|
| `STATIC` | STATIC | No noise, clipping threshold 100 (privacy-free baseline) |
| `DP` | **FUP** — Fixed Update Perturbation | Fixed clipping threshold 1.5, noise multiplier 1.0 |
| `ADP` | **AUP** — Adaptive Update Perturbation | Adaptive clipping (initial 1.0, 80th percentile of update norms, bounds [0.1, 10.0]), noise multiplier 1.0 |

The keys `DP` and `ADP` are kept in the code for database and dashboard compatibility. They correspond to FUP and AUP in the paper. The perturbation is **not** accompanied by formal epsilon-delta privacy accounting.

## Repository structure

```
.
├── Data_Preparation_Revised.ipynb        # Cleaning, 70:10:20 split, encoding/scaling, non-IID client partition, centralized reference
├── federated_server.py                   # Flask aggregation server: FedAvg, update clipping/perturbation, validation monitoring, PostgreSQL logging
├── auto_client.py                        # Hospital client: local SMOTE + local training, sends model updates to the server
├── run_experiments.py                    # Runs every scenario x seed (server + 2 clients) and builds mean ± SD tables
├── make_figures.py                       # Regenerates the result figures (Figs. 3, 5, 6) from results/
├── experiment_metadata.json              # Split, feature, and partition metadata produced by the notebook
├── centralized_reference_results.json    # Centralized reference models (comparison only)
├── client_class_distribution.csv         # Class counts per client before/after local SMOTE
├── figures/                              # All figures used in the paper (see "Figures" below)
└── results/                              # Per-run summaries, training histories, threshold sweeps, aggregated tables
```

## Dataset

This study uses the public **Diabetes Prediction Dataset** (100,000 records) from Kaggle:
https://www.kaggle.com/datasets/iammustafatz/diabetes-prediction-dataset

The dataset is not included in this repository. Download `diabetes_prediction_dataset.csv` and place it in the repository root.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

The server logs training history to a database. Set the connection string through an environment variable (do not hard-code credentials):

```bash
# Linux / macOS
export FL_DB_URI="postgresql://postgres:<password>@localhost:5432/federated_db"
# Windows (PowerShell)
$env:FL_DB_URI="postgresql://postgres:<password>@localhost:5432/federated_db"
```

Create the `federated_db` database in PostgreSQL first. The tables are created automatically when the server starts.

## Reproducing the experiments

1. **Prepare the data.** Run `Data_Preparation_Revised.ipynb` from top to bottom. It produces `client_RS_01.npz`, `client_RS_02.npz`, `server_holdout.npz`, `preprocessor.joblib`, `experiment_metadata.json`, and the figures.
2. **Run all experiments** (3 scenarios x 5 seeds x 50 rounds):
   ```bash
   python run_experiments.py
   ```
   Useful options:
   ```bash
   python run_experiments.py --scenarios ADP --seeds 1 2   # subset of runs
   python run_experiments.py --summarize_only              # rebuild tables from results/ only
   python run_experiments.py --fixed_threshold 0.5         # one common threshold for all scenarios
   ```
3. **Regenerate the result figures:** `python make_figures.py`
4. **Run a single scenario manually** (three terminals):
   ```bash
   python federated_server.py --scenario ADP --seed 1 --rounds 50
   python auto_client.py --id RS_01 --seed 1
   python auto_client.py --id RS_02 --seed 1
   ```

```bash
python make_figures.py
```

Curves show the mean over five seeds; shaded bands show ± one standard deviation. The script also prints the share of clipped client updates from round 15 onward (FUP 54.7%, AUP 1.7%), as reported in the paper.

## Results

The `results/` folder contains the outputs used in the paper:

- `all_runs_test_metrics.csv`: final test metrics for every scenario and seed
- `table_test_mean_sd_selected_threshold.csv`: mean ± SD at the validation-selected threshold (Table 6 in the paper)
- `table_test_mean_sd_threshold_050.csv`: mean ± SD at threshold 0.50
- `table_paired_differences_vs_static.csv`: paired differences against STATIC
- `training_history_*.csv`: per-round global and client metrics
- `threshold_sweep_validation_*.csv`: threshold sweep on the validation set
- `summary_*.json`: per-run summary

## Experimental protocol

- Duplicates removed before splitting; `No Info` in `smoking_history` treated as `Unknown`.
- Stratified 70:10:20 train/validation/test split; scaler and encoder fitted on the training partition only.
- SMOTE applied **locally inside each client**; validation and test sets are never resampled.
- Global model starts from random initialization (no centralized pre-training).
- Best round and decision threshold are selected on the validation set; the test set is evaluated once per run.

## Limitations

- Two simulated clients built from a public secondary dataset, not real multi-institutional records.
- No formal epsilon-delta privacy accounting; results describe update perturbation only.
- The feature scaler is fitted on the pooled training data of both clients.
